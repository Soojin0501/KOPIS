## 1. 분류 모델 성능

원래 노트북은 라벨이 있는 공연 전부로 학습하고, 그 공연들로 평가했다. 같은 그래프와 같은 설정으로 평가 방법만 바꿔 다시 쟀다.

| 평가 방법 | 표본 | 마이크로 F1 | 매크로 F1 | 정확도 | 상위 2개 정확도 |
|---|---|---|---|---|---|
| 공모전 당시 기록 | 72,612 | 0.9925 | 0.9474 | | |
| A. 원래 방식 재현 | 72,612 | 0.9934 | 0.9452 | 0.9981 | 0.9999 |
| B. 검증 분리, 학습 구간 | 58,089 | 0.9922 | 0.9367 | 0.9983 | 0.9999 |
| B. 검증 분리, 검증 구간 | 14,523 | 0.8217 | 0.6853 | 0.8375 | 0.9075 |
| C. 기준선, 검증 구간 | 14,523 | | | 0.7724 | 0.8863 |

- A 는 당시 수치를 재현한다. 코드가 같은 일을 한다는 뜻이다.
- B 의 검증 구간이 처음 보는 공연에 대한 성능이다. 정확도 0.84, 상위 2개 정확도 0.91이다.
- C 는 모델 없이 참여자들이 가장 많이 참여한 장르를 고르는 방법이다. 모델은 이 기준선보다 정확도가 6.5%p 높다.

학습 구간과 검증 구간의 차이가 크다. 노드마다 임베딩을 따로 학습하는 구조라 학습 데이터를 외우기 쉽다.

## 2. 복합 공연 예측의 검증

복합 공연에는 세부 장르 라벨이 없다. 예측이 맞는지 직접 잴 방법이 없다. 단일 공연 검증 성능이 간접 근거다.

단일 공연 검증은 "장르 하나를 맞히는가" 를 잰다. 복합 공연 예측은 "장르 둘의 조합을 맞히는가" 다. 둘은 같은 문제가 아니다. 상위 2개 정확도 0.91은 정답 장르가 상위 둘 안에 드는 비율이지, 둘째 장르가 맞는 비율이 아니다.

## 4. 성공률

| | 행 | 성공 | 실패 | 성공률 | 보고서의 "성공률" |
|---|---|---|---|---|---|
| 유료 | 53 | 33 | 20 | 62.3% | 37.7% |
| 무료 | 47 | 28 | 19 | 59.6% | 40.4% |

보고서의 값은 실패 비율과 정확히 같다. 판정 규칙(복합 점수가 두 단일 장르 평균 이상이면 성공)을 파일에 다시 적용하면 파일의 판정과 100% 일치한다. 파일이 아니라 보고서 문장이 뒤바뀐 것이다.

보고서의 해석 "복합 장르는 고위험 고성과 구조" 는 성공률 40% 를 전제로 한다. 실제 성공률은 60% 안팎이다.

한 행은 공연 한 건이 아니다. 공연장 규모와 장르 조합의 묶음이다. 53행은 조합 20가지와 규모 3단계에서 나왔다. 표본이 작아 비율이 몇 행에 따라 크게 움직인다.

공연 단위로 비교한 다른 노트북은 기준도 결과도 다르다. 두 단일 장르 중 하나만 넘으면 우세로 보았고, 유료 65.7%, 무료 48.0% 였다.

## 5. 복합과 단일의 우열

저장된 지표 결과 파일이 두 벌 있다. 좌석 수 열이 있는 것과 없는 것이다.

| 구분 | 복합 | 단일 | 차이 | 검정 |
|---|---|---|---|---|
| 유료, 좌석 수 있음 | 44.79 (472건) | 45.33 (34,173건) | -0.54 | p = 0.51 |
| 무료, 좌석 수 있음 | 50.91 (228건) | 42.80 (4,071건) | +8.11 | p < 0.001 |
| 유료, 좌석 수 없음 | 39.89 (372건) | 44.54 (33,261건) | -4.64 | p < 0.001 |
| 무료, 좌석 수 없음 | 51.77 (204건) | 41.55 (4,303건) | +10.22 | p < 0.001 |

- 무료 공연에서는 복합이 단일보다 높다. 두 벌 모두 같다.
- 유료 공연에서는 복합이 높지 않다. 한 벌에서는 차이가 없고 다른 벌에서는 복합이 낮다.
- 보고서 요약의 "복합 51.98, 단일 45.06" 에서 단일 값은 파일과 맞는다. 복합 값 51.98 은 어느 파일에서도 나오지 않았다. 전체 평균은 46.78 이다.
- 보고서의 "복합이 전반적으로 우수" 는 무료 공연에만 맞는 말이다.

보고서 요약 표에서 참여도와 규모가 같은 값으로 나온 것은 파일에서도 확인된다. 둘 다 백분위로 만든 값이라 전체 평균이 0.5 근처가 된다.

## 6. 회귀 모델

| | 유료 | 무료 |
|---|---|---|
| 전체 행 | 53 | 47 |
| 평가에 쓴 행 | 11 | 10 |
| 랜덤포레스트 설명력 | 0.92 | 0.88 |
| 선형회귀 설명력 | 0.98 | 0.99 |
| 지표 공식과 점수의 상관 | 0.99 | 1.00 |
| 가격 접근성의 서로 다른 값 | 53 | 1 |

- 지표 점수는 세 축의 가중 기하평균에 보정을 곱한 값이다. 세 축으로 점수를 예측하면 공식을 되짚는 것이다.
- 선형회귀가 랜덤포레스트보다 설명력이 높다. 보고서는 비선형 관계 때문에 랜덤포레스트를 골랐다고 했지만 이 데이터에서는 근거가 되지 않는다.
- 평가에 쓴 행이 10개 안팎이다. 설명력 수치를 믿기에 표본이 작다.
- 무료 공연의 가격 접근성은 값이 하나뿐이다. 중요도가 0 으로 나온 것은 발견이 아니라 당연한 결과다.
- "참여도를 0.10 올리면 실패의 80% 가 성공으로 바뀐다" 는 공식에 값을 넣은 계산이다. 실제 공연에서 참여도를 올리는 방법이나 비용은 다루지 않는다.

## 7. 재현성

같은 코드로 다시 학습한 예측을 저장된 예측과 비교했다.

| 비교 | 일치율 |
|---|---|
| 첫째 장르가 같음 | 67.2% |
| 장르 조합이 같음 | 41.7% |

원래 코드는 난수 씨앗을 고정하지 않았다. 저장소에 남은 예측 파일 다섯 개도 서로 다르다. 같은 공연이 실행마다 다른 조합을 받았다.

뒤 단계의 성과 비교는 저장된 예측 한 벌에 의존한다. 예측이 달라지면 조합별 성공과 실패도 달라진다.

## 그 밖에 확인한 것

- 보고서는 공연과 장르를 엣지로 연결했다고 썼다. 코드에는 그 엣지가 없다. 장르 노드는 만들었지만 어디에도 연결되지 않았다. 결과적으로 정답이 그래프로 새지 않아 다행이다.
- 보고서는 지표를 가중 합으로 설명했다. 코드는 가중 기하평균이다.
- 클래스 가중치의 분모에 학습 표본 수가 아니라 전체 노드 수를 썼다. 모든 장르의 가중치가 의도보다 크다.
- 엣지 가중치가 0 인 엣지가 10,090개(2.3%) 있다. 이름이 어휘에서 빠진 경우다.
- 성과 분석에 쓴 복합 표본 705건 중 129건은 예측 장르가 비어 있다.

## 다시 쓴다면

1. 검증 구간을 나눠 성능을 보고한다.
2. 난수 씨앗을 고정하고, 여러 번 학습해 예측이 얼마나 흔들리는지 함께 보고한다.
3. 둘째 장르에 확률 기준을 둔다. 기준을 넘지 못하면 조합을 정하지 않는다.
4. 단순 기준선과 비교해 모델이 더한 몫을 밝힌다.
5. 복합과 단일의 비교는 유료와 무료를 나눠 말한다.
6. 회귀 모델 대신 지표 공식으로 직접 계산한다.
7. 공연에 고유 식별자를 붙이고 관계형 모델로 관리한다. [관계형 데이터 모델](../schema/README.md)
